## Why 001 was shipped

It is the only finding that breaks the core collaborative loop for every user during
ordinary use. The client flushes every 60 ms (`canvas.tsx:862`) against a 240/min
**per-board** D1 budget (`room.ts:450`). About 15 s of drawing in a minute closes the
tab with 1013, and the reconnect loops until the window rolls over. The fix is small,
contained to the room, and fully verifiable by the repo's own Vitest, typecheck,
lint and build gates. Four new room tests fail on `cecd0eb` and pass after the change.

The sibling repo system-design-companion merged the same fix as its PR #55. This
repo was forked from it and carries the identical gap (same cadence, limit and close
code), so this is a real defect here and not a speculative duplicate. The other
findings are either narrower (004), affect only subscribed hosts (002), or appear
only after ~30 agent edits (003).

## Findings considered and rejected

- Shared-link editing without sign-in: intentional capability access (`README.md`, `docs/design.md`).
- Socket messages awaiting D1 interleaving out of order: once 001 lands, there is no await. Before it, the merge rule compared against live state after the await, so stale versions were rejected anyway.
- `restore(snapshotId)` building an R2 key from the input: the prefix is fixed to this room's `snapshots/<diagramId>/`, and R2 keys are not normalized, so another room's snapshot cannot be addressed.
- Snapshot write ordering (R2 then D1) not being atomic: already documented in `docs/improvements.md` as a known cross-store limitation.
